# SEO & Indexing Runbook

One-time and per-release steps to keep `go-pretty-converter`'s site
(`https://sazardev.github.io/go-pretty-converter/`) indexed, fresh, and ranking.

## How the site is published

- The site is static HTML in `_site/` (gitignored), generated by
  `go run ./scripts/docsgen` from `README.md` + `docs/cli.md` + `CHANGELOG.md`.
- `.github/workflows/docs.yml` runs on every push touching docs/README/examples
  (or `workflow_dispatch`), generates `_site/`, appends the two demo PDFs
  (`library-demo.pdf`, `full-demo.pdf`), and deploys to GitHub Pages.
- Sitemap, robots.txt, meta tags, og/twitter cards, and JSON-LD are all
  generated by `scripts/docsgen` — never hand-edit `_site/`.

### What's already in place

| Asset | Where | Notes |
|---|---|---|
| `robots.txt` | generated | `Allow: /` for all + explicit allow for search/LLM/social bots; points at the sitemap |
| `sitemap.xml` | generated | both HTML pages, `llms.txt`/`llms-full.txt`, `docs.md`, `humans.txt`, all theme PDFs/EPUBs, demo PDFs, with `lastmod`/priority |
| Canonicals | `<head>` | self-referencing on `/` and `/docs.html` |
| JSON-LD | `<head>` | Organization, WebSite, SoftwareApplication (landing + docs), FAQPage (landing), BreadcrumbList (docs) |
| OG / Twitter | `<head>` | `og:image` 1200x630 (dark gruvbox card), type, locale, alt |
| `llms.txt` / `llms-full.txt` | generated | AI-crawler friendly docs export |
| `humans.txt` / `version.json` | generated | attribution + machine-readable metadata |
| Meta description | `<head>` | 152 chars, unique per page |

## One-time setup (do once, then it's automatic)

### 1. Google Search Console

1. Go to <https://search.google.com/search-console> → **Add property** →
   **URL prefix** → `https://sazardev.github.io/go-pretty-converter/`.
   (Verification: as the `sazardev` account owns the `github.io` subdomain you
   can pick the simplest method — upload the HTML meta tag file into the repo
   temporarily, or use the GitHub method if available.)
2. **Sitemaps** → submit `sitemap.xml` → expect "Success".
3. **URL Inspection** for `https://sazardev.github.io/go-pretty-converter/` and
   `/docs.html` → **Request indexing** for each.

### 2. Bing Webmaster Tools

1. <https://www.bing.com/webmasters> → add site
   `https://sazardev.github.io/go-pretty-converter/`.
2. Either **import from Google Search Console** (one click, if both use the
   same Google account) or paste the GSC verification meta tag.
3. **Sitemaps** → submit `sitemap.xml`. Bing also feeds Copilot/Edge results,
   so this covers Microsoft surfaces too.

### 3. GitHub repo social preview

GitHub uses its own OG image for the repo card (linked from the site, pkg.go.dev,
Hacker News, etc.) — independent of the site's og-image.

1. Generate/preview it: `go run ./scripts/docsgen` already produces
   `_site/og-image.png` (1200x630).
2. In the repo **Settings → Social preview** upload that PNG (or keep the
   default). Note: `_site/` is gitignored, so download it from
   <https://sazardev.github.io/go-pretty-converter/og-image.png> (or regenerate and
   copy it out) before uploading.

## Per-release checks

After each deploy (verify on the live URL):

- [ ] `https://sazardev.github.io/go-pretty-converter/` returns 200 and shows the
      new description/title.
- [ ] `https://sazardev.github.io/go-pretty-converter/docs.html` returns 200.
- [ ] `sitemap.xml` has today's `lastmod` and lists the current theme count
      (17 PDFs/EPUBs).
- [ ] GSC **Crawl → Sitemaps** still reports "Success" (it auto-re-fetches).
- [ ] GSC **URL Inspection** → "URL is on Google" for `/` and `/docs.html`.
- [ ] No new 404s in GSC **Pages** — the site's own PDF quality audit also
      flags broken in-document anchors on every `build`.

## Fixing indexation problems

| Symptom | Likely cause | Fix |
|---|---|---|
| Page not indexed | Not requested yet | URL Inspection → Request indexing |
| Stale description/snippet | Google re-crawls slowly | Request indexing; update `siteDescription` in `scripts/docsgen/main.go` |
| "Crawled – currently not indexed" | Low perceived value / thin content | Wait; the docs page is deliberately one large page. Keep `lastmod` fresh |
| New theme not in sitemap | Sitemap regenerated before push | Just redeploy; `docs.yml` regenerates the sitemap from `theme.List()` |
| Duplicate/odd URLs (`report.json`, `version.json`, `docs-search.json`) | They're generated artifacts in the sitemap | Optional: remove the `addURL(...)` lines in `scripts/docsgen/seo.go` — they're indexable but not ranking pages |

## Key commands

```bash
go run ./scripts/docsgen            # regenerate _site/ locally (needs Chrome)
curl -s https://sazardev.github.io/go-pretty-converter/sitemap.xml | head
# trigger a rebuild + deploy without code changes:
#  gh workflow run docs.yml   (or push an empty commit)
```

## Content freshness

`lastmod` in the sitemap is the build date, so every docs/README change bumps
it automatically — there is nothing to update by hand. The `og:updated_time`
and JSON-LD dates are generated the same way.
